# Experimental native image generation

Native image generation is disabled by default. It is a hosted OpenAI Responses
tool: the model decides when to call it after a prompt such as "generate a logo."
It is supported for the `openai` and `openai-codex` providers.

Enable it explicitly on a provider in the agent's configuration:

```json
{
  "providers": [
    {
      "name": "openai-codex",
      "default": true,
      "builtins": {
        "image_generation": {
          "enabled": true,
          "options": {
            "model": "gpt-image-2.5-flare",
            "quality": "low",
            "size": "1024x1024",
            "output_format": "png"
          }
        }
      }
    }
  ]
}
```

Set `enabled` to `false` to disable the capability. Listing `image_generation` in
`builtin_tools` alone does not enable it. The flag and options survive provider
and reasoning clones. The legacy provider-level `image_generation` object is
also accepted (with model/options directly inside it); generic settings take
precedence. Server's managed-agent hydration currently forwards the legacy form.
Use the generic form through Core's config file/API until Server forwards the
`builtins` map. See [builtin-capabilities.md](builtin-capabilities.md).
Normal agent config updates/restarts apply the gate; this change does not enable
it on any existing agent or deploy a release.

The image model is separate from the provider's reasoning model. If `model` is
omitted, the upstream chooses its default image model. There is no automatic
fallback to another image model or billing route if the configured one is denied.

## Transport and shared files

When enabled, Core routes Responses calls through Server's internal
`/api/runtime-image-responses` gateway. The process must have `SERVER_URL`,
`AGENT_ID`, and `AGENT_SECRET` (legacy `INSTANCE_SECRET` also works), plus the
provider's normal credential. Server supplies these to managed Core processes.
Core supplies the actual caller thread separately from model arguments.

Server receives the hosted image bytes, stores them using existing durable blob
storage and access grants, and substitutes a `file_ref` into the outgoing stream:

```json
{
  "_file": true,
  "ref": "blobref://...",
  "filename": "generated-image.png",
  "mimeType": "image/png",
  "size": 12345
}
```

Core retains this metadata in assistant content parts and emits `image.generated`
telemetry with the same handles. The next model turn can pass the reference to a
compatible file tool. No generated image bytes reach Core, its local BlobStore,
provider continuation state, session history, or model context. Missing gateway
context is an error; Core never falls back to receiving image bytes directly.

This first rollout generates new images (`action: generate`). It supports PNG,
JPEG, and WebP results. Partial preview payloads are discarded at the gateway.
Editing shared blob inputs and preview rendering are not included in this rollout.
Server caps each blob at 25 MiB, each SSE event at 40 MiB, and each request at
eight images / 100 MiB of generated bytes. Failed/truncated streams are errors;
an interrupted call may already have stored an image, and an inference retry can
generate another image. Duplicate final items within one stream reuse its handle.

## Verification

Deterministic tests run in the normal short suites. The live test uses a temporary
Server database and a local gateway, then launches Core's live test against real
OpenAI endpoints. It validates generation, persisted metadata, a real LLM tool
call passing the unchanged ref, gateway resolution of the actual image, and
tool-result continuation. It does not start or reconfigure an existing agent.

From `server/`:

```sh
RUN_NATIVE_IMAGE_GENERATION_LIVE=1 go test -v -count=1 \
  -run '^TestNativeImageGenerationLive$' -timeout 6m .
```

The default is `openai-codex`, reasoning model `gpt-6.1-sol`, and image model
`gpt-image-2.5-flare`. Codex credentials come from `OPENAI_CODEX_ACCESS_TOKEN` or
the existing local `~/.codex/auth.json`. Account identity comes from
`OPENAI_CODEX_ACCOUNT_ID` or that auth file. An explicitly requested live run
fails if its credential is unavailable; it does not silently skip.

Use `APTEVA_IMAGE_GENERATION_LIVE_PROVIDER=openai` with `OPENAI_API_KEY` for API
billing. Override the exact models with `APTEVA_IMAGE_GENERATION_LIVE_MODEL` and
`APTEVA_IMAGE_GENERATION_LIVE_IMAGE_MODEL`. Live tests consume provider usage.
`APTEVA_IMAGE_GENERATION_GATEWAY_URL` overrides the gateway URL for isolated tests.
Set `APTEVA_IMAGE_GENERATION_LIVE_OUTPUT` to an absolute PNG path to preserve the
test's image for review. Server exports it before the temporary database is removed.

On 2026-10-03 the real Codex + GPT Image 2.5 Flare test passed: it produced a
780,529-byte PNG, consumed it through the shared blob interface, and completed
the subsequent native function-tool turn. This verifies that account/route at
test time; it does not establish availability for every subscription account.
